# 第六轮：完整单 Agent 工具系统

日期：2026-10-31

## 交付内容

本轮将原来仅做规范抽取的 `alinea_agent` 扩展为持久化、可恢复的单 Agent 工具系统，保留原确定性 DOCX 引擎和人工审批边界。

- 新增 AgentRun/AgentEvent、项目作用域 API、后台执行、启动恢复、运行预算及脱敏工具轨迹。
- Agent 可读取项目上下文和规范片段、校验规则及冲突、提出结构化澄清、读取文档结构、给出独立角色建议、提交检查、读取 Issue、准备 DRAFT 修复计划和读取验证报告。
- 模型没有 Shell、任意文件系统、规则/计划批准或修复执行工具。修复仍通过原用户审批页面执行。
- 兼容不支持 `json_schema` response format 的 OpenAI 兼容端点：模型返回 JSON 文本，服务端使用 Pydantic 严格解析。
- 项目工作区新增桌面侧栏和移动抽屉，默认突出结论、澄清与主要操作，工具轨迹折叠显示。
- 默认模型配置改为 DeepSeek；密钥只通过临时进程环境用于验收，未写入源码、配置示例或报告。

## 真实模型验收

使用用户指定的端点和 `deepseek-flash`：

1. 规范抽取得到 3 条原子规则，来源证据及 Pydantic 校验通过。
2. Agents SDK 真实多步循环调用项目上下文、规范读取与规则校验工具，生成 3 条规则，不是单次文本抽取。
3. 草案规则未批准时，Agent 拒绝提交检查并进入 NEEDS_CLARIFICATION。
4. 通过原审批 API 批准规则后，Agent 依次调用项目上下文、提交检查、读取检查摘要，AgentRun 为 SUCCEEDED，并明确说明下游检查仍排队，未虚报通过。
5. 修复后的分发及启动恢复使该 Inspection 实际完成为 SUCCEEDED：20 项明确违规、24 项 UNKNOWN、19 项可修复、42 个定位结果。

真实模型调用与使用可重复模型替身的自动化测试分别记录，不互相替代。

## 复杂文档

保留用户提供的江苏大学 `.doc` 原文件不变，LibreOffice 成功转换分析副本。解析结果为 200 个段落、6 个分节、26 个样式，识别到文本框、域和外部关系。

新增可重建合成样例 `tests/fixtures/data/alinea-agent-complex.docx`：47 个段落、3 个分节、164 个样式，包含多级标题、中英文混排、图片、图题、合并表格、公式、页码域、外链、横竖分节和参考文献。复杂样例完成真实上传、角色建议、规则批准、检查分发、LibreOffice 渲染及检查读取；当前文档版本未被 Agent 改写。

生成命令：`.venv/Scripts/python tests/fixtures/generate_agent_complex.py`。

## 修复的问题

- DeepSeek 拒绝 Agents SDK 默认 `json_schema` 响应格式，改为严格 JSON 文本解析。
- Agent 工具曾把 Inspection 的“复用”返回值误作“新建”，导致新检查只排队不分发；现统一为 QUEUED 即分发，并有回归断言。
- 工具异常原会随事务回滚丢失失败事件；现先提交失败轨迹再向模型返回错误。
- 检查工具已统一到同一权限、预算、事件与事务执行路径。

## 尚未完成与边界

- 真实浏览器交互验收在用户手动接管浏览器后暂停，未将其列为通过；前端单测、类型和构建不能替代该浏览器闭环。
- 角色建议只作为独立建议保存，不会自动覆盖解析角色；尚未实现批量人工角色确认编辑器。
- 真实高校模板只完成转换和结构解析，不代表已人工核对全部学校规范或 Microsoft Word 视觉效果。
- 本轮未进行 Docker、公网、真实 RQ 集群或多进程竞争验收；既有 mypy 类型债务不在本轮修复范围。
