# Alinea 第三轮：操作简化与商业工作台验收

验收完成日期：2026-10-26

## 结论

本轮将网页主线收敛为 **上传与规范 → 检查与选择 → 批准与修复 → 报告与下载**，减少路由跳转、重复检查和默认技术信息，同时增加渐进展开、自然过渡和移动端主操作。后端重复检查复用、历史证据保护与任务查询优化已落地。

**这是本地真实文件与浏览器验收，不是生产发布承诺。** 原稿不可变、人工批准、包级 OOXML 补丁、G1–G5、preview SHA/revision 绑定均未改变。前两轮报告保留不变。

## 主要改进

### 后端：减少重复工作并保护历史

- 同 Key 先验证请求摘要；同 revision、规则 digest、检查器版本可复用活动 Job 或成功 Inspection。成功记录的摘要、问题、预览和警告不被重写，也不改变 RepairPlan 的证据输入。
- `reused` 只在 POST 响应中表达本次是否复用。修复产生的 after-inspection 没有 inspection Job 时，可创建真实完成的 `CACHED` Job 和 status URL，但不 dispatch。
- mapping 不兼容明确返回 409；FAILED 仍需显式安全重试。取消的未产出检查可由用户明确重新提交。
- 重复重试先返回已有 retry Job，再考虑任何实体变更，避免清掉已成功或被 RepairPlan 引用的历史。
- 新建写入采用 nested transaction；唯一冲突后必须重新验证归属、请求摘要和 mapping 才允许复用，不能把数据库异常直接当成成功。当前同项目 API 创建使用进程内锁，未把该锁宣称为跨进程一致性证明。
- 项目 Job 列表改为一次 Job 查询和一次批量 JobEvent 查询，空事件列表不回源，移除 1+N 事件查询。

### 前端：减少选择成本与信息密度

- `WorkflowRail` 提供四步导航、真实完成状态和结果步骤准入；项目栏只保留项目名、短版本与同步状态，完整信息可去任务记录查看。
- 新建页默认真实 `general_report`，修复旧默认 `general_academic` 不存在的问题。文件名自动命名，支持两套非官方预设、文本与 PDF；高级设置折叠。
- `InspectionSetupPanel` 将文档、规范版本、来源和启用规则集中展示。规范批准后可立即开始检查，修复计划和执行仍需独立批准。
- 刷新结果只读取已有数据并核对 revision/digest，不把旧结果显示为重新评估。失败可安全重试，取消可重新提交；复用成功结果时直接加载，不空等状态变化。
- 修复页默认显示易读 before→after、影响范围和前三项操作；完整 digest、UUID、OOXML 约束按需展开。完成后的计划徽标同步为真实完成状态。
- 结果页分为“结论 / 对照 / 下载”。双 PDF 页码、缩放和旋转保留；下载页集中提供修订版、原版、JSON、Markdown 和证据指纹。
- 长渲染环境 JSON 改为按需展开，普通警告仍直接展示，证据没有删除。

### 动效与响应式

- 步骤、面板、折叠、对话框和移动窗格使用分层过渡；主要动画使用 opacity/transform，减少布局抖动。
- 折叠使用 Vue enter/leave 与渐进式 `interpolate-size: allow-keywords`，在固定 0 与自然高度之间过渡；不采用脆弱的 max-height 猜测，其他浏览器保留即时高度与淡入淡出。
- 离开过渡完成后移除节点，折叠的高级字段不会阻断表单提交。
- 系统与手动减少动效均有效，没有恢复全局 `0.01ms` 压制。
- 移动端提供短步骤标签、独立窗格切换和选中后的底部修复操作区，保留安全区与内部表格滚动。

真实脚本还验证了：不同 Key 的重复检查复用原 Inspection/Job；成功重试后再次重试返回同一 retry Job，Inspection、RepairPlan、报告和发布结果保持不变。修复执行与重试共 2 个 repair Job，但只有 1 个发布版本。

## 浏览器实际检查

- 新建页：真实默认预设、文件名自动命名、高级设置展开/收起、有效上传与规范提取状态。
- 检查确认：文档、规范版本、启用规则、来源与主按钮集中显示；规范批准使用原生对话框。
- 检查与修复：选择 I-01、I-02，生成差异摘要；批准计划后单独执行，真实进度与完成徽标正确。
- 结果：默认结论、双版本对照、文件下载三个视图可切换；DOCX、JSON、Markdown 下载均真实发生。
- 移动端：390px 新建页、四步导航、历史入口、问题窗格、底部修复操作与结果视图可用，没有根级横向溢出。
- 减少动效：系统变化与手动选择均生效，刷新后保持；折叠内容可展开并正确移除。

## 安全与代码复核

- 项目 token 仍只以 SHA-256 持久化，嵌套资源重新检查项目归属；未新增公开文件 URL 或绕过审批的路径。
- 复用与重试不会清空成功历史；mapping 不足时不会伪造定位或 PDF。未修改原 DOCX、批准边界、包级补丁或 G1–G5。
- 未新增运行时依赖、在线字体、动画库或 CloudBase 资源。密钥仅通过本地进程环境使用，没有写入源码、`.env.example` 或报告。
- 已按相关 CloudBase code-review 规则复核敏感 runtime 信息和会话边界；项目使用本地项目 token，不使用 CloudBase Auth/SDK，因此没有将云平台特定会话规则误当成已部署能力。
- HTTP 未新增完整 headers、环境变量或 runtime context 回显。源代码范围密钥扫描未发现真实模型密钥。
